Field guide · what was built, why, and how

DEBATE ARENA UNDER THE HOOD

Two AI debaters argue a topic over three rounds, an AI judge scores them, and every line can be read aloud. This guide follows one request through the system, explains each decision, and shows what the build taught about working with Claude.

Version 1 · claude.ai artifact

Free, shareable, no server

A single page hosted by claude.ai. It borrows each viewer's own Claude access through the sample capability and speaks with the browser's built-in voices.

Version 2 · Cloudflare Worker

Your site, your keys, real voices

The same page served from Cloudflare, plus a small server that holds your Anthropic and ElevenLabs keys, checks a passcode, and caps daily use.

2 · One debate, start to finish

What happens when you press Start

A debate is nine model calls in a fixed order. None of them remembers the others: Claude has no memory between calls, so the page rebuilds the full context every time.

  1. Cast the debaters

    One call asks Claude for two contrasting characters as JSON: a name, an emoji, a personality and, on the hosted site, a voice from the list of 12. Typed personas keep your words; Claude only names and voices them.

    1 call · sample.json · counts toward the daily cap

    Peek at the prompt shape 
    We are staging a funny debate between two characters on this topic: "Is cereal a soup?"
Side FOR argues in favor of the topic. Side AGAINST argues against it.
FOR character: invent one that is funny and appropriate to the topic.
…
Respond with JSON only, in exactly this shape:
{"for":{"name":"...","emoji":"...","personality":"...","voice":"<voice key>"}, …}

  2. Six streamed turns

    Opening, Rebuttal, Closing; For speaks first each round. Each call carries the persona, the round's goal, the rules (about 120 words, no markdown, stay in character) and every word said so far. Text appears as it is written.

    6 calls · sample with onText · Server-Sent Events on the hosted site

    Peek at a rebuttal prompt 
    You are Captain Grimbeard, a character in a lighthearted debate. Your personality: a grumpy 1800s pirate.
The debate topic is: "Is cereal a soup?"
You are arguing FOR the topic; your opponent, Professor Prim, is arguing AGAINST it.
This is the Rebuttal round. Rebut your opponent: attack their weakest points…
Respond directly to your opponent's specific points, quoting or paraphrasing what they actually said…
Debate so far:
Captain Grimbeard (FOR, Opening): …
Professor Prim (AGAINST, Opening): …
Now give your Rebuttal speech as Captain Grimbeard, arguing FOR the topic: in character, at most ~120 words…

  3. Speak each turn

    With Voice on, the finished turn is sent to ElevenLabs in that debater's voice and played before the next turn starts. If anything fails (credits gone, voice retired, outage), that turn switches to the browser's own voice.

    7 clips including the verdict · /api/tts → MP3

  4. The judge rules

    A weary Supreme Court justice reads the whole transcript and returns scores as JSON: logic, persuasion and character, 1 to 10 each. The page checks every number and lets the totals pick the winner, because a model can name a winner that contradicts its own scores.

    1 call · sample.json · normalizeVerdict() validates it

3 · What this taught about Claude

Eight capabilities, and where they show up in the code

Personas are just instructions

There is no special persona feature. A name, a personality line and “stay in character” are enough for Claude to hold a voice across a whole debate. Change one sentence and the debate changes completely.

logic.js · buildTurnPrompt()

Claude is stateless

Each call starts from nothing. Conversation “memory” is the app re-sending the transcript, which is why later turns cost more and why the Under the hood panel shows the prompt getting longer.

app.js · transcript[] passed every turn

Instructions belong near the end

In a long prompt, rules placed only at the top get diluted. The turn prompt repeats the key rules after the transcript, right before Claude writes. A reviewer added this after spotting the risk.

logic.js · closing reminder line

Streaming makes it feel alive

Text arrives in small deltas instead of one block. On the hosted site the Worker relays Anthropic's Server-Sent Events (content_block_delta) to the page as they arrive.

worker/sample.js · src/hosted.js

Ask for JSON, then check it

Claude follows a JSON shape well, but the code still validates every field: scores clamped to 1–10, strings like "8" accepted, unknown voices replaced, garbage rejected with a Retry button.

logic.js · normalizePersonas(), normalizeVerdict()

AI as a judge needs a rubric

The judge gets defined criteria, a scale, a valid example and the rule “higher total wins”. Even so, the code lets the totals decide, because the stated winner and the scores can disagree.

logic.js · buildJudgePrompt()

Model settings matter

The server calls claude-sonnet-5-5 with the lowest thinking setting so the 1,024-token budget goes to the speech, sends no temperature (this API version rejects it), and enables server-side fallback for reliability.

worker/sample.js · request body

Plan for “no”

Claude can decline a request, rate limits happen, and viewers can refuse permission. Each case has its own message and recovery path: refused turns are cleared, rate limits offer a retry, permanent refusals stop asking.

app.js · errorCopy(), PERMANENT codes

4 · Decisions and trade-offs

Why it is built this way

DecisionWhyTrade-off accepted
Plain HTML and JavaScript, no frameworkRuns as a claude.ai artifact unchanged; nothing to build or install.More manual DOM code than React would need.
One front end, two adaptersapp.js asks for a sample object; claude.ai or hosted.js supplies it. Fixes land in both versions at once.The adapter must mimic the claude.ai API exactly, including error codes.
Keys live only in the WorkerAnything in a web page can be read by its visitors. The server adds keys on the way out.Requires hosting a server instead of a static page.
Passcode plus signed cookieStops strangers spending your credits, without user accounts.Anyone with the passcode can use it; change it to revoke.
Daily cap in a Durable ObjectA single counter that can't be raced: 20 debates a day, plus call backstops if a tampered page skips the count.The limit is shared by everyone using the site.
Sonnet 5.5, not OpusFast and capable enough for 120-word speeches; cheaper per debate.Slightly less nuanced arguments than the largest model.
ElevenLabs Flash v2.5Lowest latency and half the credit cost per character.Less expressive than ElevenLabs' top models.
Browser voices as fallbackFree voices retire on December 31 and credits run out; debates should never go silent.Fallback voices sound robotic.
All text set with textContentModel output is untrusted. A turn containing HTML shows as text instead of running.No rich formatting in speeches (which the prompt forbids anyway).

5 · How it was built

A small team of models, with review gates

The build used the delegated-build skill: one lead plans and verifies, cheaper models do focused work, and every task is reviewed by a fresh agent before it is pushed. Each builder wrote tests first and watched them fail before writing code.

Opus · lead

Plan and verify

Wrote the specs and plan, briefed each agent, re-ran every test suite before pushing.

Sonnet · builders

Write the code

One task each, tests first, with a short report back. Never pushed their own work.

Haiku · researchers

Look things up

Read ElevenLabs' docs and found that the default voices retire on Dec 31.

Opus · reviewers

Gate each task

Checked against the plan, hunted for bugs, fixed them with a test per fix.

  1. T1
    Prompts and validation. Caught: “smile” became the emoji “s”; a capitalised “For” winner was ignored.
  2. T2
    Page and streaming debate. Caught: the setup form never hid during a debate; Stop could break after a quick restart.
  3. T3
    Judge scorecard and retries. Caught: typed personas were all named “Debater For / Against”.
  4. T4
    Whole-app review. Caught: the same topic replayed a cached debate; the judge could crown the lower total.
  5. T5
    Browser voices. Caught: iPhones would stay silent because speech didn't start inside a tap.
  6. T6
    Worker core. Caught: refusals passed off as finished turns; a memory leak in the login limiter.
  7. T7
    Passcode screen and adapter. Caught: debates double-counted; the daily cap could be bypassed; garbled emoji.
  8. T8
    ElevenLabs voices. Caught: a busy moment was mistaken for running out of credits.
  9. T9
    Security and deploy review. Caught: a missing key used up daily slots; unclear setup errors.

7 · Learn by changing it

Five experiments to try

  • Easy · no code

    Watch the context grow

    Run a debate, then open “Under the hood” on the first and last bubbles. Compare what Claude was sent.

  • Easy · one line

    Recast the judge

    In buildJudgePrompt(), swap “a weary Supreme Court justice” for “an over-excited game show host”. Notice how the reasoning changes but the scores stay sensible.

  • Medium

    Add a fourth round

    Add “Cross-examination” to ROUNDS with a goal in ROUND_GOALS. Watch which tests fail; they show you every place that assumed three rounds.

  • Medium

    Tune the cost guard

    Change DAILY_CAP in wrangler.jsonc, push, and see Cloudflare redeploy automatically.

  • Stretch

    Let the audience vote

    Ask Claude Code to add a vote button before the verdict and compare the crowd with the judge. Start with the brainstorming step, as this project did.

8 · Glossary

Terms used above

Artifact
A web page hosted by claude.ai. It can be granted runtime capabilities, such as calling Claude as the viewer.
Messages API
Anthropic's API for sending a conversation to Claude and getting a reply, used by the hosted Worker.
Streaming (SSE)
Server-Sent Events: the reply arrives as many small events instead of one response.
Stateless
Each model call knows only what is in that call. History must be re-sent.
Structured output
Asking the model to answer in a fixed format such as JSON, so code can read it.
LLM-as-judge
Using a model to evaluate other model output against a rubric.
Cloudflare Worker
A small server program that runs on Cloudflare's network with no machine to manage.
Durable Object
A Cloudflare object with its own storage that handles one request at a time, ideal for counters.
Secret
An encrypted setting only the server can read, such as an API key.
Spec, plan, review
The build process: agree what to build, break it into tasks, and have a fresh agent check each one.
